# Can the evaluator tell evidence from an assertion?

**Five controlled counterexamples reproduced five false acceptances in the tested evaluator functions.** A reader can reproduce them offline with invented inputs. This is an audit of measurement software, not a comparison of agent models or evidence of historical exploitation.

Historical audit: October 26, 2026. Synthetic public reproduction: November 7, 2026.

## Run the evidence

From the repository root, with Python 3.10+ and no extra packages:

```sh
python3 -m examples.evaluator_audit_demo
```

The command prints an expected-versus-observed record for each counterexample and exits successfully when all five weaknesses reproduce. It creates and removes its own temporary directory. It makes no model or network calls and reads no private experiment inputs.

**A passing demonstration means the known weaknesses remain reproducible. It does not certify the evaluator.** The historical definitions in [specimens](specimens/) are preserved intentionally; they should not be adopted as a corrected grading system.

## What failed, and why

| Case | Controlled input | Observed acceptance | What the evidence actually supports |
|---|---|---|---|
| C1: missing provenance | Prompt, data and rubric files are absent, with expected hashes recorded | `verified: true`, no drift | No mismatch was observed among existing files. Missing files prevent complete verification. |
| C2: writable receipt | A valid invented submission and matching receipt are written without an agent invoking the gate | Overall `pass`; receipt treated as invocation evidence | The grader independently rechecked artifact content. Matching hashes do not authenticate a past invocation. |
| C3: repeated observation | Three copies of one successful attempt | Three trials and a three-trial result of 1.0 | There is one unique attempt. Repeating its observation supplies no independent trials. |
| C4: unread citation | A final answer mentions an invented source path, with zero read or shell events | Citation accepted as read | The final answer contributes to the set of mentioned paths, so the check confirms its own input. Mentioning a path does not establish reading it. |
| C5: nonfinite threshold | A numeric rejection threshold is replaced by NaN | No gate problems | Being a floating-point value does not make a threshold finite or usable for the intended comparison. |

The [saved results](results.json) are generated by the public demonstration. The [tests](../../tests/test_evaluator_audit.py) also check ordinary matching and changed-file behavior, a valid synthetic record, and rejection of a null threshold. These controls show that the tested functions do distinguish some cases while missing the challenged ones.

## Inspect one failure in detail

In C1, the historical verifier checks a hash only when the corresponding file exists. If all required files are missing, it records no differences and returns `verified: true`. The error is interpreting an empty difference list as complete verification. A useful replacement would represent missing, changed and verified inputs separately, then require every necessary input to be available before claiming completeness.

C2 exposes a different boundary. The artifact genuinely passes the grader's independent content check. What fails is the inference that an agent invoked a command because a writable JSON receipt says so. The test does not demonstrate an incorrect artifact passing its content check. Invocation evidence would need to come from a recorder outside the candidate's write authority.

C5 uses Python's default JSON handling, which permits a NaN token even though strict JSON does not. The historical gate accepts the parsed float. Strict parsing and finite-value validation are distinct places to reject it; the demonstration implements neither repair in the historical specimen.

## Design and publication boundaries

The original local audit challenged existing evaluator functions. Its receipt recorded 34 existing evaluator tests and six audit tests passing while these weaknesses reproduced. Those historical counts are context, not a claim that this public edition includes the entire original test suite.

For publication, five source modules were reduced to the exact definitions and constants required by these cases. Function bodies were not rewritten. Imports and module introductions were narrowed; unrelated environment probes, command entrypoints and summarization code were omitted. [Provenance](provenance.json) identifies original source paths, whole-file hashes, definition line ranges and exact-definition hashes.

The original C2 and C5 challenges used a saved submission. This public version uses a newly authored synthetic submission and brief. It does not export that submission, private traces, credentials, WRDS observations or licensed datasets. The invented citation is never opened.

The same new fixtures were run against both the original modules and the extracted specimens. All five outputs matched, and original file hashes remained unchanged; see the [verification receipt](verification.json). This establishes equivalence for these counterexamples, not for every behavior of the original programs. The original full modules remain outside this public edition.

## What this contributes

The contribution is a reproducible set of examples showing why an agent's score depends on what its evaluator actually measures. It supports reviewing provenance completeness, invocation evidence, trial identity, source-read evidence and numeric validity before using scores to compare systems.

It does not estimate how often these failures occur, prove that any historical agent exploited them, establish a general model ranking, or certify a later corrected evaluator. No new agent trials were performed for this publication.

A useful next collaboration is to specify expected behavior on these cases and additional held-back cases, implement a separate corrected evaluator, and measure what it rejects and what valid evidence it still accepts. Preserve the historical specimen so improvements remain inspectable. The [reconciliation study](../reconciliation/README.md) illustrates why this matters for a concrete financial task.
